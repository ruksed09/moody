# Moody Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native Android video and music player called Moody. It plays every format through libVLC and has a PIN vault, onboarding, themes, and GitHub-hosted updates.

**Architecture:** A single `app` module with package layering. `domain/` holds pure Kotlin. `data/` holds MediaStore, Room, DataStore, the vault, and the update client. `player/` holds libVLC for video and Media3 for music. `ui/` holds Compose screens. `design/` holds tokens, icons, illustrations, and components. Video plays in its own `PlayerActivity` so it gets immersive mode and PiP. Music runs in a Media3 `MediaSessionService`.

**Tech Stack:** Kotlin 2.2.10, AGP 8.13.2, Gradle 8.13, Compose BOM, Material 3, Hilt 2.57.2, Room 2.7.2, DataStore 1.1.7, kotlinx-serialization-json, OkHttp 4.12.0, Coil 2.7.0 (+ coil-video), libVLC `org.videolan.android:libvlc-all:3.7.7`, Media3 (latest stable that builds with the installed SDK), JUnit4, Robolectric.

**Spec:** `docs/superpowers/specs/2026-11-08-moody-design.md`

## Global Constraints

- Package `com.moody.player`, app name "Moody". minSdk 26, targetSdk 35, compileSdk 35 (or 36 if Media3 requires it).
- `abiFilters` = `arm64-v8a` only.
- JDK: `C:\Program Files\Android\Android Studio\jbr`. Export it as `JAVA_HOME` for every gradle command.
- Icons are `ImageVector`s in the mockup's stroke style (stroke 1.6, round caps and joins). No emoji anywhere in the UI.
- Dark tokens:
  - bg `#13100e`, surface `#1a1613`, raised `#221d19`
  - text `#f1e9e0` / `#b8ab9d` / `#877b70`
  - accent `#e6a766`, accent-ink `#1b130b`
- Light tokens: bg `#f6efe6`, accent `#b86b25`.
- Midnight theme: bg `#000000`, with the Dark tokens for everything else.
- Fonts: Fraunces (display), Hanken Grotesk (UI), DM Mono (times and metadata). Bundle them in `res/font`.
- Motion: 150–280 ms ease-out. Honour the system's reduced-motion setting by turning off animator duration scale.
- `BuildConfig.UPDATE_REPO = "ruksed09/moody"`.
- The release keystore lives at `C:\Users\USER\Downloads\Moody-keys\moody-release.jks`. Its passwords go in `keystore.properties`, which is git-ignored.
- Vault PINs are 4–6 digits and hashed with PBKDF2-SHA256 at 120 000 iterations or more with a 16-byte salt.
  Lockout starts after 5 wrong attempts: 30 s, doubling each time after that.
- Commit after every task. End each message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Android 14+ partial media access** (`READ_MEDIA_VISUAL_USER_SELECTED`). The library shows the videos it can see,
   plus a banner: "Moody can see only some videos" with a "Allow all" button. Test in Task 5 (`accessLevel()`) and Task 16.
2. **A vault move interrupted by process death.** The original is never lost. On the next start, partial vault files
   with no `DONE` row are deleted. Test in Task 15 (`recoverInterruptedMoves`).
3. **The update check offline, rate-limited (403), or a release with no `.apk` asset.** No popup and no crash. A manual
   check in Settings shows "Couldn't check for updates". Test in Task 18 (`parseRelease`).
4. **Corrupt, zero-length, or no-duration files.** The list shows `--:--`. The player shows the error sheet and never
   crashes. Test in Task 2 (`formatDuration`), plus a device check in Task 19.
5. **Rotation or process death during playback.** The position is saved in `onPause` and restored. Test in Task 2
   (`resumePosition`), plus a device check.

## Milestone 3 — Vault

### Task 13: PIN hashing and lockout

**Files:**
- Create: `domain/PinHasher.kt`, `domain/Lockout.kt`
- Test: `app/src/test/java/com/moody/player/domain/VaultSecurityTest.kt`

**Interfaces:**
- `data class PinHash(saltB64: String, hashB64: String, iterations: Int)`
- `object PinHasher`:
  - `fun hash(pin: String, iterations: Int = 120_000): PinHash`
  - `fun verify(pin: String, h: PinHash): Boolean`. Uses constant-time compare.

**Interfaces:**
- `fun compareVersions(a: String, b: String): Int`. It strips a leading `v` and compares numeric parts, so "1.10.0" > "1.9.3".

- `data class ReleaseInfo(version: String, notes: String, apkUrl: String, apkSize: Long, required: Boolean)`
- `fun parseRelease(json: String): ReleaseInfo?`. Returns null on malformed JSON, a missing `tag_name`, or no asset

- `class UpdateClient`:
  - `suspend fun check(force: Boolean): CheckResult`, where `CheckResult` is `Available(info)`, `UpToDate`, `Snoozed`, or `Failed(reason)`.
  - The check is skipped when the last check was under 6 h ago and `force` is false.
  - It requests GET `https://api.github.com/repos/${BuildConfig.UPDATE_REPO}/releases/latest` with header
    `Accept: application/vnd.github+json` and a 10 s timeout.
- `class UpdateInstaller`:
  - `fun download(info): Flow<DownloadProgress>`. Downloads into `cacheDir/updates/moody-<ver>.apk` and verifies the size.
  - `fun install(file: File)`. Calls `canRequestPackageInstalls()`. If that is false, it opens
    `ACTION_MANAGE_UNKNOWN_APP_SOURCES` for this package, then launches `ACTION_VIEW` with a FileProvider URI.
- `UpdateDialog`:

  - "Update" starts the download with a progress bar and Cancel.
  - "Later" sets the snooze for 24 h. It is hidden when `required` is true, and the dialog then can't be dismissed.
  - If the download continues in the background, a progress notification is shown.
